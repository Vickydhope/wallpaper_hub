## Project overview

Wallpaper Hub is a Flutter app that browses/searches wallpapers from the Pexels API (`https://api.pexels.com`) and downloads them via `flutter_downloader`.

## Common commands

```bash
flutter pub get                       # install dependencies

# Code generation (required after changing @injectable classes, @RestApi
# services, or json_serializable models — e.g. wallpaper_api_service.dart,
# injection.dart, any *.g.dart source)
dart run build_runner build --delete-conflicting-outputs
dart run build_runner watch --delete-conflicting-outputs   # watch mode

flutter analyze                       # static analysis (flutter_lints)
flutter test                          # run all tests
flutter test test/widget_test.dart    # run a single test file
flutter run                           # run on a connected device/simulator
```

iOS-specific: after adding/upgrading a plugin, run `cd ios && pod install`.

## Architecture

Feature-first Clean Architecture with `get_it` + `injectable` for DI and `flutter_bloc` for state management.

```
lib/src/
  config/
    di/               # get_it + injectable setup; injection.config.dart is GENERATED
                       # (run build_runner after adding @injectable/@module classes)
    base_url/          # BaseUrlConfig — Pexels base URL and endpoint prefixes
  core/
    data/interceptor/  # Dio interceptors (e.g. token_interceptor)
    resources/         # DataState<T> (DataSuccess/DataFailed) — repository return type
    utils/
      errors/          # ErrorHandler + Failure + DataSource enum: maps DioException ->
                       # typed Failure with a user-facing message
      sealed/          # ApiState / DownloadState sealed classes for bloc UI states
      usecase/         # UseCase<Type, Param> abstract base (call({required param}))
      mapper/          # DtoMapper<Type> — DTOs implement toEntity()
    presentation/      # shared widgets (cached photo widget, shimmer, hero)
  features/<feature>/
    data/
      datasources/remote/  # Retrofit + Dio @RestApi service (needs codegen, .g.dart)
      model/                # DTOs (json_serializable), each implements DtoMapper -> Entity
      repositories/         # *RepositoryImpl, @Injectable(as: <RepositoryInterface>)
    domain/
      entity/               # plain domain entities returned to the UI layer
      repository/           # abstract repository interface
      usecases/             # one class per use case, @injectable, wraps a repository call
    ui/
      bloc/<name>/          # bloc + event + state (part files), @injectable
      pages/, widgets/      # Flutter UI
```

Data flow: `UI (bloc event)` -> `UseCase` -> `Repository` (abstract, in domain) -> `RepositoryImpl` (in data, calls the Retrofit `ApiService`) -> DTO -> `.toEntity()` -> `Entity` back up through `DataState<T>` -> bloc emits `ApiState` (`InitialState`/`LoadingState`/`SuccessState`/`ErrorState`) consumed by the page via `BlocBuilder`/`BlocConsumer`.

Only one feature exists currently: `wallpapers` (curated photos, search, and photo download). Follow its structure (`lib/src/features/wallpapers/**`) as the template for any new feature.

### Dependency injection

- Classes are wired via `@injectable` / `@Injectable(as: Interface)` / `@module` annotations and resolved through `locator` (`GetIt.instance`, `lib/src/config/di/injection.dart`).
- `injection.config.dart` is generated by `build_runner` — do not hand-edit it; change the annotated source and regenerate.
- Environments `production`/`development` are defined in `injection.dart` but the app currently always configures with `development`.

### Networking & error handling

- `AppModule.provideDio` builds the shared `Dio` client with `TokenInterceptor` and a logging interceptor.
- API services are Retrofit interfaces (`@RestApi()`) with generated `*.g.dart` implementations — add new endpoints there and rerun codegen.
- Repository implementations catch exceptions and convert them to `DataState` via `ErrorHandler.handle(error).failure`; `ErrorHandler` maps `DioException` types/status codes to a `Failure(code, message)` using the `DataSource` enum in `lib/src/core/utils/errors/error_handler.dart`. Follow this pattern (don't throw raw exceptions to the UI layer).

### Downloads (flutter_downloader)

- Initialized in `main.dart` before `runApp` via `FlutterDownloader.initialize(debug: true, ignoreSsl: true)`.
- On iOS, `flutter_downloader` requires `FlutterDownloaderPlugin.setPluginRegistrantCallback` to be set in `AppDelegate.swift` (registers plugins on the background isolate the plugin spins up for downloads) — without it, starting a download crashes with `NSAssert(registerPlugins != nil, ...)`.
- `DownloadPhotoBloc` (`lib/src/features/wallpapers/ui/bloc/download_photo/`) is the entry point for download UI state; wire actual `flutter_downloader` task enqueue/progress handling through it.

### Config values

- Pexels API key lives in `lib/src/core/constants.dart` (`AppConstants.pixelApiKey`) — currently unused by the interceptor/headers; check `TokenInterceptor` before assuming auth is wired up.
- `BaseUrlConfig` (`lib/src/config/base_url/base_url_config.dart`) holds the base URL and endpoint path prefixes (`/v1`, `/videos`).
